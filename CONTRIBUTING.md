# Como contribuir

O projeto é desenvolvido em equipe utilizando Git e GitHub.

## Fluxo de trabalho

1. Consulte ou crie uma Issue explicando a tarefa.
2. Atualize a branch main antes de começar.
3. Crie uma branch específica para a alteração.
4. Faça as modificações e teste o sistema no navegador.
5. Registre as mudanças com commits claros.
6. Envie a branch ao GitHub e abra um Pull Request.
7. Solicite a revisão de outro integrante do grupo.
8. Resolva eventuais conflitos e ajustes antes de integrar à main.

## Padrão dos commits

Utilizamos Conventional Commits:

- feat: nova funcionalidade
- fix: correção de erro
- docs: alteração na documentação
- style: ajustes de estilo
- refactor: reorganização do código

Exemplo: `feat: adicionar exportacao do historico`.

## Antes de aprovar um Pull Request

- Conferir se a alteração corresponde à Issue.
- Testar as funcionalidades afetadas.
- Verificar se o gráfico, histórico e classificação continuam funcionando.
- Conferir a documentação quando houver mudança de comportamento.
- Registrar a revisão no GitHub.

## Versões

As versões estáveis devem receber uma tag e uma release no GitHub. As principais mudanças devem ser registradas no CHANGELOG.md.

O sistema utiliza dados simulados ou inseridos manualmente e possui finalidade acadêmica.
